Lighthouse 12.8.2, headless Chromium (Playwright build 1248), Windows 10, one run per cell, default throttling.
Mobile is the default preset (simulated slow 4G, 4x CPU) and desktop is `--preset=desktop`.
Scores are listed as Performance / Accessibility / Best practices / SEO.

Top opportunities on the live site:

- **library.html**: each of the ~70 `<video preload="metadata">` clips fetched about 250 KB from GitHub Releases at load, which came to 8.7 MB on mobile. The page also spent a lot of main-thread time painting them.
- **exercises.html**:
  - The Google Fonts stylesheet (Heebo) blocks rendering, costing 0.7 s on desktop and 1.5 s on mobile.
  - The poster JPEGs (540–810 × 1080, about 160 KB each, 42 files, 6.8 MB) are shown at thumbnail size. Lighthouse estimates 6.2 MB could be saved with properly sized images and 1.7 MB more with WebP or AVIF.
  - CLS on desktop is 0.49, and the shift is on `<html>`, which points to the web-font swap.
  - The LCP element is the first poster.
- **index.html / weekly.html**: the Sentry CDN bundle (`browser.sentry-cdn.com`) was requested while the `<head>` was being parsed (Lighthouse flagged "preconnect"). On weekly.html, `core.js` and `reel-library.js` in the `<head>` block rendering.
- **Every page**: GitHub Pages caches for 10 minutes (`cache-insight`). This can't be configured on Pages.

## Fixes in this PR

1. **Lazy-load library clips** (`js/core.js`, `TH.mediaMarkup`):
   - The URL of a `<video>` clip is parked in `data-th-src`, and an IntersectionObserver (400 px margin) moves it to `src` once its card is near the viewport.
   - A MutationObserver picks up clips that the pages add later.
   - Without these observers (or under Node), `src` is written directly as before.
   - Drive and YouTube iframes already used `loading="lazy"`.
   - This works on every page that renders clips: library, index result, and workout mode, where the current clip is in view and loads immediately.
2. **Load Sentry after the page** (`js/sentry-init.js`):
   - The CDN bundle is appended on `window` `load` instead of during head parsing, so it no longer competes with the page's own CSS and JS.
   - Errors thrown before it arrives are still buffered (up to 10) and sent after init, as before.

## Follow-ups not done here

Most HTML pages are being changed in open PR #529, and `js/reel-library.js` / `data/drive_videos.json` in #528. This PR doesn't touch them to avoid conflicts.

- **exercises.html** (#529):
  - Self-host Heebo, or load it without blocking rendering (`media="print" onload` or `preload`), plus a fallback with matching metrics. Expected gains: about 0.5–1.7 s FCP and most of the 0.4–0.5 desktop CLS.
  - Add `loading="lazy" decoding="async"` and `width`/`height` to the poster `<img>` (rendered around line 320), keeping the first row eager because it holds the LCP image.
- **weekly.html** (#529): add `defer` to the `core.js` / `reel-library.js` tags in the `<head>` (about 150–260 ms of render blocking on mobile). This needs a check that the inline scripts run after them.
- **assets/posters/*.jpg**: resize to about 2× the displayed size (around 360 px wide) and/or add WebP. That is about 6 MB less, but it is a lossy re-encode, so it needs an owner decision. No lossless JPEG optimizer was available on this machine.
- **Caching**: GitHub Pages fixes `max-age=600`. Long-term caching would need versioned file names, which isn't worth it for this demo.
